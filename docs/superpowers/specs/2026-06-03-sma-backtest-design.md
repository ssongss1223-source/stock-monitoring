## 3. 전략 로직

### 3-1. 진입 필터
```
종가 > SMA(sma_period)  AND
종가 <= 최근 lookback_days 종가 고점 × (1 - drawdown_pct / 100)
```
- 고점 기준: 최근 lookback_days 동안의 **종가** 최고값 (intraday high 아님)
- 낙폭 조건은 **첫 SMA 돌파일에만** 체크 (이후 분할매수는 SMA 조건만)

### 3-2. 분할매수
```
confirm_days = 3:
  Day 1: 진입 필터 통과 → 1/3 매수  (+수수료 0.03%)
  Day 2: 종가 > SMA     → 1/3 추가  (+수수료 0.03%)
          종가 < SMA     → 전량 손절  (+수수료 0.03%)
  Day 3: 종가 > SMA     → 1/3 추가  (+수수료 0.03%)
          종가 < SMA     → 전량 손절  (+수수료 0.03%)

confirm_days = 1:
  Day 1: 진입 필터 통과 → 100% 일괄매수 (+수수료 0.03%)
```

### 3-3. 단계별 익절 (완전 매수 후 보유 중)
기준: 평균 매수가 대비 수익률

| 수익 달성 | 매도 수량 | 수수료 |
|----------|----------|--------|
| +10% | 보유분의 10% | 0.03% |
| +25% | 보유분의 10% | 0.03% |
| +50% | 보유분의 10% | 0.03% |
| +100% | 보유분의 50% | 0.03% |
| +200% | 보유분의 50% | 0.03% |

### 3-4. SMA 청산 (잔여 포지션)
```
종가 < SMA(sma_period) → 잔여 전량 매도 당일 (+수수료 0.03%)
```

## 5. Walk-forward 설계

```
Train: 5년 (1,260거래일)
Test:  2년  (504거래일)
Step:  1년  (252거래일)

2005~2025 데이터 기준 약 8~10개 윈도우:
  [2005~2010 학습] → [2010~2012 검증]
  [2006~2011 학습] → [2011~2013 검증]
  ...
  [2018~2023 학습] → [2023~2025 검증]
```

- 검증 구간 성과를 평균 → 최적 파라미터 선정
- 데이터 7년 미만 종목: Walk-forward 스킵, 인샘플 전체 사용, 결과에 ⚠️ 표시

## 6. 성과 지표

| 지표 | 설명 | 역할 |
|------|------|------|
| **Calmar Ratio** | CAGR ÷ MDD | **최적화 1순위** |
| CAGR | 연평균 수익률 | 참고 |
| MDD | 최대 낙폭 | 리스크 한도 |
| 손익비 | 평균익절 ÷ 평균손절 | 전략 건강성 |
| 기대값 (EV) | 승률×평균익절 - 패율×평균손절 | 진입 1회 기댓값 |
| 승률 | 익절 거래 / 전체 거래 | 참고 |
| Buy & Hold 대비 | 전략 - 단순 보유 | 전략 우위 확인 |
| 총 거래 수 | | 신뢰도 판단 |

> 거래 수 10개 미만 파라미터 조합은 결과에서 제외 (통계적 신뢰도 부족)

## 7. 컴포넌트 구조

```
backtest/
  sma_config.py       ← 23종목 목록, 파라미터 그리드, 고정값 정의
  sma_signal.py       ← SMA / 낙폭 필터 / 포지션 상태 계산
  sma_backtester.py   ← 단일 파라미터 조합 백테스트, 거래 기록, 지표 계산
  sma_optimizer.py    ← Walk-forward 루프, 그리드서치, 최적 파라미터 도출
  sma_reporter.py     ← 텔레그램 메시지 포맷

dashboard/
  sma_dashboard.py    ← Streamlit MVP (FastAPI 연동 후 Next.js 교체 가능)

api/
  sma_api.py          ← FastAPI 엔드포인트 (결과 조회, 종목별 최적값)
```

> Streamlit은 MVP 전용. 백엔드(FastAPI + DuckDB)를 처음부터 분리 설계하여 Next.js 교체 용이하게 유지.

## 8. 결과 저장 (DuckDB)

```sql
CREATE TABLE sma_backtest_results (
    ticker          VARCHAR,
    run_date        DATE,
    sma_period      INTEGER,
    confirm_days    INTEGER,
    lookback_days   INTEGER,
    drawdown_pct    DOUBLE,
    -- Walk-forward 정보
    is_walkforward  BOOLEAN,
    window_start    DATE,
    window_end      DATE,
    -- 성과 지표
    calmar          DOUBLE,
    cagr            DOUBLE,
    mdd             DOUBLE,
    win_rate        DOUBLE,
    profit_factor   DOUBLE,
    ev              DOUBLE,
    total_trades    INTEGER,
    vs_buyhold      DOUBLE,
    PRIMARY KEY (ticker, run_date, sma_period, confirm_days,
                 lookback_days, drawdown_pct, window_start)
);
```
